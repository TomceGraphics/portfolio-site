01. SYSTEM ARCHITECTURE

Database Specialization

Relational databases hit bottlenecks when forced to manage live hierarchical arrays, real-time networking, and recursive reference mappings all at once.

BlockSync delegates application states to three specialized database engines, utilizing Docker environments to maintain absolute operational separation.

MongoDB Authoritative Document Store

Stores users, nested folders, and ordered arrays of document blocks. Document flexibility makes it optimal for structural rearrangments and rich text blocks without schemas mapping issues.

Neo4j Semantic & Permission Graph

Maps user access boundaries, page containments, and bidirectional links (`[[wiki-links]]`). Converts expensive regex queries and recursive joins into direct O(1) graph traversals.

Redis Volatile RAM Cache & Event Bus

Manages online user presence registries with automated TTL expirations, caches active documents, and acts as a Redis Pub/Sub cluster bus for distributed socket instances.

02. HUMAN FACTORS & COGNITIVE DESIGN

Designing for the Design Technologist

Protecting the User's "Flow State"

In human-centered design, the motor-sensory loop relies on immediate visual feedback. Studies show that latency above **100ms** breaks the illusion of direct manipulation, introducing friction to the writing process.

If the system attempts to commit changes to a persistent store (MongoDB & Neo4j) on every single keystroke, the event loop blocks, introducing slight stuttering. Decoupling the pipeline guarantees typing loops remain sub-millisecond, preserving the author's flow.

Mapping Cognitive Mental Models

Standard operating systems rely on nested folder paths—a physical model that doesn't match the human brain's semantic network. Humans retrieve memories via association (connections between concepts).

By overlaying a wiki-link structure (`[[Page]]`) modeled in Neo4j, BlockSync bridges this conceptual gap. Users build associative connections dynamically, navigating workspaces through semantic associations rather than mechanical directory paths.

Direct Manipulation of Content Blocks

In traditional writing tools, a document is a single string of characters. This treats the text as a monolithic canvas rather than distinct conceptual units.

BlockSync implements a modular block structure. Bullet points, headers, and code arrays are distinct blocks that can be rearranged directly. This spatial alignment matches the user's intent to reorganize outlines on the fly.

Visibility of System Status & Presence

Real-time collaboration can be disorienting without proper visibility of co-presence. High-frequency network events are combined with ephemeral room caching in Redis to prevent visual clutter.

Collaborator indicators, active room rosters, and clean "saving..." triggers in the HUD guide the user's understanding of system stability, reinforcing user trust and reducing confusion.

// From backend/services/graphService.js
// Parses Wiki-Links and writes them in Neo4j in a single Transaction
async syncWikiLinks(fromPageId, blocks) {
  const session = driver.session();
  try {
    const linkPattern = /\[\[(.*?)\]\]/g;
    const targetTitles = new Set();

    blocks.forEach(block => {
      if (block.content) {
        let match;
        while ((match = linkPattern.exec(block.content)) !== null) {
          targetTitles.add(match[1].trim());
        }
      }
    });
    const targets = Array.from(targetTitles);

    // 1. Delete previous outgoing links to establish a clean slate
    await session.executeWrite(tx =>
      tx.run(
        'MATCH (from:Page {id: $fromPageId})-[r:LINKS_TO]->(:Page) DELETE r',
        { fromPageId: fromPageId.toString() }
      )
    );

    if (targets.length === 0) return;

    // 2. Merge target pages and link them
    await session.executeWrite(tx =>
      tx.run(
        `MATCH (from:Page {id: $fromPageId})
         UNWIND $targets AS targetTitle
         MERGE (to:Page {title: targetTitle})
         ON CREATE SET to.id = randomUUID()
         MERGE (from)-[:LINKS_TO]->(to)`,
        { fromPageId: fromPageId.toString(), targets }
      )
    );
  } finally {
    await session.close();
  }
}
// From backend/services/graphService.js
// Runs periodically to reconcile graph state with authoritative MongoDB
async syncWorkspaceFromMongo(workspaceId, mongoDocs) {
  const session = driver.session();
  try {
    const mongoIds = mongoDocs.map(d => d.id.toString());

    // 1. Rebuild current pages and link them to the workspace node
    if (mongoDocs.length > 0) {
      await session.executeWrite(tx =>
        tx.run(
          `MERGE (w:Workspace {id: $workspaceId})
           WITH w
           UNWIND $pages AS page
           MERGE (p:Page {id: page.id})
           SET p.title = page.title
           MERGE (w)-[:CONTAINS]->(p)`,
          {
            workspaceId: workspaceId.toString(),
            pages: mongoDocs.map(d => ({ id: d.id, title: d.title }))
          }
        )
      );
    }

    // 2. Delete nodes in Neo4j that are no longer in MongoDB
    await session.executeWrite(tx =>
      tx.run(
        `MATCH (w:Workspace {id: $workspaceId})-[:CONTAINS]->(p:Page)
         WHERE NOT p.id IN $mongoIds
         DETACH DELETE p`,
        { workspaceId: workspaceId.toString(), mongoIds }
      )
    );
  } finally {
    await session.close();
  }
}

// Utilizes ephemeral cache for presence registries
const Redis = require('ioredis');
const redis = new Redis(process.env.REDIS_URL);

async function registerPresence(documentId, socketId, user) {
  const presenceKey = `presence:${documentId}:${socketId}`;
  
  // Save user info in Redis, expiring after 1 Hour to clear inactive nodes
  await redis.set(
    presenceKey, 
    JSON.stringify({
      username: user.username,
      avatarColor: user.avatarColor,
      activeAt: Date.now()
    }),
    'EX',
    3600 
  );
}

async function getOnlineUsers(documentId) {
  const pattern = `presence:${documentId}:*`;
  const keys = await redis.keys(pattern);
  if (keys.length === 0) return [];
  
  const values = await redis.mget(keys);
  return values.map(val => JSON.parse(val));
}
06. ARCHITECTURE RETROSPECTIVE

System Trade-Offs

Ephemeral Typing Latency vs. System Fault Tolerance

By keeping characters inside the client's volatile memory buffer during the 1200ms debounce interval, we shield the databases from high-frequency write operations. However, this optimization exposes users to minor data loss risks: if the browser process crashes mid-sentence, characters written since the last database write are lost.

HCI Justification: We prioritized cognitive comfort (smooth, stutter-free interfaces) over absolute persistent consistency of incomplete words. A 1200ms loss boundary is negligible compared to the mental exhaustion of laggy writing components.

The Conflict Resolution Challenge

Since this project was built without complex OT (Operational Transformations) or CRDTs (Conflict-free Replicated Data Types), concurrent edits hitting the same document block are resolved by standard "last-write-wins" database operations.

Future Roadmap: Implementing a block-level CRDT algorithm (e.g., Yjs) inside the debounced pipeline would allow multiple users to edit the same blocks simultaneously, resolving merge collisions deterministically.

Polyglot Persistence Drift

Distributing application state across MongoDB and Neo4j opens up risks of database divergence. If a page is renamed or deleted, but the Neo4j API call fails, the graph nodes become out of alignment.

Mitigation Strategy: We built a background Graph Reconciliation cron script that queries MongoDB for active document IDs and synchronizes the Neo4j graph nodes dynamically, cleaning up dead references.
